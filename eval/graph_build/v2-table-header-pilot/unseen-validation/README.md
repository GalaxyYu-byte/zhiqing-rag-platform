# 6 份未参与规则设计的 xlsx 留出检查

输入为仓库 `dox/` 下另 6 份 xlsx 测试材料，排除了冻结 v1 的 83.xlsx、89.xlsx（按文件哈希排除）。它们是虚构企业测试材料，并非真实生产文档。脚本 `scripts/verify_graph_table_unseen.py` 本地解析并重分块，没有调用模型或数据库。

- **分块结构：**6 份文档产生 13 个数据 Chunk；13/13 均以原工作表第 3 行的真实列头开头，保留 `table_header_row=3`，且不超过 512 token。`chunk_checks.jsonl` 记录来源哈希、Chunk 哈希和列头。
- **当前 Chunk 的证据：**选择其中两份不同列结构的表格，共生成 30 条候选关系。15 条 `主责角色 --RESPONSIBLE_FOR--> 环节`，15 条 `文件或成果 --GOVERNED_BY--> 检查要点`。30/30 均通过关系端点 Schema、原文逐字校验，并且两端名称与证据在同一数据行；`fact_candidates.jsonl` 提供逐条核查。
- **语义初审：**Codex 查看了 30 条候选及所在列。责任关系列明确给出主责角色与环节；保管检查列给出每项文件或成果的检查要点，初步支持 `GOVERNED_BY`。部分“文件或成果”单元格命名更像内容描述，`Material` 实体边界和类型应由业务人员复核。未发现明显关系方向颠倒或否定条件丢失；此检查不构成独立人工 Gold。

这验证了新分块结果提供**可定位的行列证据**，尚不能报告 Evidence Precision。留出材料来自同一项目的相似模板；更广泛的表格格式仍需单独验证。`summary.json` 给出计数，所有输入和输出保留在本地。
