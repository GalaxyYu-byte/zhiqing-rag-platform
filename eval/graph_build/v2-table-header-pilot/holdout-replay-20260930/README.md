## 结论：暂不采用实验提示词

2026-09-30，已按用户授权将固定的 13 个测试 Chunk 发送给当前配置的 DeepSeek。

没有 PostgreSQL/Neo4j 写入，生产提示词、现有图谱及原冻结基线均未改变。

13 块中 **10 块通过结构与逐字校验，3 块失败**。其中一块仅含表格范围说明，返回空结果；

## 三块失败的根因

| Chunk | 来源 | 最终错误 |
| --- | --- | --- |
| holdout-04-01 | 版本发布前核对清单 | EVIDENCE_INVALID |
| holdout-05-01 | 费用凭证核验要点 | OUTPUT_EMPTY_AFTER_INVALID |
| holdout-05-02 | 费用凭证核验要点 | EVIDENCE_INVALID |

三块的引文大多确实在原文，真正不合规的是 **实体 name/canonical_name 被模型自行加词或改写**。
例如“变更清单”改成“核对变更清单”，“出行目的与行程变化”改成“说明出行目的与行程变化”，
“必要性与真实性分别核对”改成“核对必要性与真实性”。这些名称不是输入里的连续原文。

其中发生“非空无效输出 → 重试空结果”；此前增加的保护没有将这种空结果当成成功。
各次原始响应保存在 `replay.jsonl`，逐字段失败明细保存在 `failure_diagnostics.jsonl`。
本轮未将可筛选候选回填成成功结果，也未降低原文校验条件。

## Normalization 与覆盖风险

本轮各 Chunk 内，没有发现“同类型、形式归一化后同名”的重复实体组。
这不能推出 Duplicate Entity Rate 为 0：同义词、实体边界及跨 Chunk 合并尚未人工确认。
也未写实际图谱，不能给出投影后的 Merge Error Rate 或重复实体率。
“合同经办人”出现在不同 Chunk 中是重复提及，不自动算成不同实体重复或误合并。

还有两个不能被 50/57 掩盖的覆盖风险：

- 权限职责矩阵每行四个角色动作，第一块有 8 行；仅这些角色和动作就可能超过提示词的 25 实体预算。预测集中在前部，尾行覆盖不足。
- 采购第一块实际返回 **42 个实体**，超过提示词要求的 25，但仍低于当前 Schema 的 80 上限而被接受。提示词预算目前不是硬校验。

未生成正式最终 Precision/F1、Unsupported Fact Rate、Normalization 错误率。

## 下一步修复顺序

1. 先处理名称补词与类型来源：名称必须取连续原文；角色来自责任列，不从检查分类猜 Actor；检查要点保持 Rule 语义。
2. 阻止无依据的状态流转、无条件 NEXT_STEP、跨行关系；明确暂停/退回和否定的语义表达。
3. 让表格拆块预算与角色/动作列数量对应，并明确抽取器的实体上限；单靠“最多 25 个”提示词不能保证尾行覆盖。
4. 人工裁决实体边界、条件和 52 条证据不足候选，补全其余四份文档的 Gold。

本轮留出集已暴露问题，后续可作为回归集。若用它来调整规则或提示词，下一次泛化验收须另选未参与调整的样本。
正式采用前仍需完整基线复测与 PostgreSQL→Neo4j 投影一致性验证。
