## 需要解决的明显问题

1. **并列内容误抽成先后关系**：原文要求“经办意见、批准决定、实际执行和结果验收应分别表述”，
   预测却建立了 `经办意见 --NEXT_STEP--> 批准决定`。
2. **表格列语义错误**：“员工知道主要联络角色”是完成判断，被建成 Step；
   “发现说明错误”等维护触发情形被建成 State。
3. **规则对象错配**：权限清单的组织规则被绑定到复核表。

图谱构建成功和证据可定位并不代表上述关系正确。当前已发布图谱仍为 v1 抽取结果，
此前的 v2 名称反馈与表头修复尚未用于重建这批图谱。

## Demo 验收方式

- 功能：选少量代表文档完成构建，能查出职责、字段等关系并带回原文。
- 完整性：没有断边、无证据 Fact、错批次或明显重复。
- 事实质量：重点复测上述明确错误，再用小样本检查关系是否有依据；歧义先保留为待核实。

后续只围绕这些检查修复、复测并给出通过/未通过结论。
当前不新增逐条人工裁决要求，也不以补齐全量人工 Gold 作为 Demo 验收的前置条件。

## Precision / Recall / F1 参考结果

以下单独使用 **6 份表格、13 个 Chunk 的 Gold 扩展草稿**及 v3 预算/类型修复的最终隔离抽取结果。
它与上面的 10 份已发布文档实测不是同一批输出；这些指标用于 Demo 诊断与回归。

| 对象 | Precision（保守参考） | Recall（已标目标） | F1（同口径参考） |
| --- | ---: | ---: | ---: |
| Entity | 84.13% | 91.60% | 87.71% |
| Relation | 69.93% | 87.35% | 77.68% |

- Entity：已知严格匹配 371；预测 441；Gold 目标 405。匹配要求类型与规范名称一致。
- Relation：已知严格匹配 214；预测 306；Gold 目标 245。匹配要求 source、relation_type、target 和方向一致。
- 计算：Precision参考 = 已知匹配数 / 预测数；Recall = 匹配数 / 已标目标数；F1参考 = 2×匹配数 /（预测数+目标数）。

Gold 是未穷尽的参考草稿，未命中预测保留为未决，不自动判成 FP。
因此 Precision/F1 是保守的已知 Gold 匹配参考，不能当成最终全量质量分数。
三元组命中不同时证明条件效果或语义证据正确；完整人工 Gold 未逐条签收。
这些是看过预测后补标的诊断数据，不作为独立留出验收成绩。
