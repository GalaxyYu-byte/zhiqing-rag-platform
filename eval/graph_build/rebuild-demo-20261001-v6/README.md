## 问题如何解决

### 1. 不能只靠提示词

v4 收紧条件、规则对象和字段定义后仍有错误；v5 要求关系证据覆盖两端及条件后，发现职责对象错配和否定反转。
最终采用 `graph-extractor-v6`，增加程序校验及修正反馈：

- 每条关系的逐字证据同时覆盖两端实体名；不能只摘目标名称或一段规则。
- 显式前置条件保留在 condition_text 和同一证据中，也检查被模型从引文裁掉的原句条件。
- 字段关系需要明确内容归属表达或表格结构，不能把“核对属性”自动当成字段定义。
- 职责关系不能把动作中的收件人、被联系方当成执行人。
- “而不是删除”等明确否定范围内的动作不能生成肯定操作关系；禁止 Rule 仍可保留。

这些是保守规则，不能代替完整语义判断，可能减少合理但证据不够直接的关系。
最后一次校验失败时只保留已通过校验的实体和关系，不通过的候选仍保留错误日志；空候选不自动获得验收通过。

### 2. 候选中的语义歧义由 Codex 裁决

v6 生成 83 条候选关系。检查全部候选关系后，剔除 16 条错误或歧义关系，保留 67 条：

| 文档 | v6 候选 Fact | 裁决剔除 | 最终 Fact |
| --- | ---: | ---: | ---: |
| 56 | 22 | 5 | 17 |
| 71 | 34 | 6 | 28 |
| 76 | 27 | 5 | 22 |

典型剔除包括并列动作推先后、把通知接收岗位当升级对象、把风险解释当规则、
把客户确认扩展成客户负责通知和关闭，以及缺乏依据的材料输入要求。
只修改未发布候选；原始模型缓存保持不变，逐条剔除理由和缓存指纹存入候选任务。
Neo4j 重投影后重新核对预期稳定键与数量，再抽查 5 条/文档。审核报告绑定实际图指纹，旧报告不能直接用于切换。

**通过的是“程序校验＋Codex 裁决后的这批 Demo 图谱”，不是未裁决的模型原始输出已全部正确。**
后续新文档不会自动套用这 16 条裁决；仍应按小样本验收。

### 3. 安全切换

候选结构、事实抽查和核心查询通过后，再次核对当前文档批次和旧活动投影。
逐文档在 PostgreSQL 事务中切换 READY；旧节点、证据和缓存保留，没有触发旧版本清理。
切换后从活动投影读取真实命名空间进行带证据查询。
