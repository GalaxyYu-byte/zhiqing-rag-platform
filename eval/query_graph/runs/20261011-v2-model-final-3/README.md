# 第二版冻结实现真实组件对照

完整 15 组运行，脚本退出 0，使用冻结虚构原文、真实 Neo4j 及 DashScope。
五份文档各用本次独立 namespace；`cleanup=true`、`cleanup_errors=[]`，所有隔离节点与 fence 已定向清理。

| 模式 | 路径执行与出处检查 | 正题完整回答证据检查 | 两道负题 | 正题耗时中位数 |

三道两跳正题分别完整回答采购表单字段、购置需求单明示别名及设备登记字段，并保留对应前提。
引用扩展只使用草稿原本选择的当前来源，未添加图三元组事实；别名题执行一次受限修复，其余两题无需修复。
缺少字段来源或同名材料属于不同流程时，未发布猜测。

`answer_evidence_checks_passed` 是开发集结构与字段覆盖检查；独立逐条事实结论见 `manual_review.json`。
以上比较使用同一五题、来源、向量、候选预算 30 和 Top-K 2，不能把开发题的优势推广为生产准确率提升。
固定组件仓储、确定性抽取、实体分析及本地排序不替代真实 PostgreSQL/HTTP 权限链。
